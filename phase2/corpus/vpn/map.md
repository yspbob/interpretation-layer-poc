# vpn — subsystem map (NetBox @ ea4c205)

## What it is

`vpn` is the Django app that models three related things: point-to-multipoint tunnels (TunnelGroup, Tunnel, TunnelTermination), the IKE/IPSec parameter hierarchy that secures them (IKEProposal → IKEPolicy, IPSecProposal → IPSecPolicy, IPSecProfile), and layer-2 VPN services with their attachment points (L2VPN, L2VPNTermination). It is 41 modules and 7,153 lines of code with 6 test modules [fg:subsystems:vpn]. It is mounted at `/vpn/` and `/api/vpn/` from the project URL conf [code:netbox/netbox/urls.py:34] [code:netbox/netbox/urls.py:53] and listed as an installed app [code:netbox/netbox/settings.py:439].

**Views and URLs**: `vpn.views` is a flat file of 70 view classes, seven per model (list, detail, edit, delete, bulk import, bulk edit, bulk delete), each registered with `register_model_view` [fg:modules:vpn.views] [code:netbox/vpn/views.py:13-67]. `vpn.urls` contains no explicit routes; every pattern is generated by `get_model_urls` for the ten model names [code:netbox/vpn/urls.py:9-37] [fg:entrypoints:vpn.urls].

**Forms**: four files split by purpose — `model_forms` (11 forms, including the extra TunnelCreateForm), `bulk_edit`, `bulk_import`, `filtersets` (10 each) [fg:modules:vpn.forms.model_forms] [fg:modules:vpn.forms.bulk_edit] [fg:modules:vpn.forms.bulk_import] [fg:modules:vpn.forms.filtersets].

**Tables**: three files mirroring the model split, all subclassing NetBoxTable; the Tunnel and L2VPN tables add TenancyColumnsMixin [fg:symbols:vpn.tables.tunnels:TunnelTable] [fg:symbols:vpn.tables.l2vpn:L2VPNTable].

**Filtersets**: one file with 10 django-filter FilterSets; Tunnel and L2VPN mix in TenancyFilterSet and ContactModelFilterSet, TunnelGroup uses OrganizationalModelFilterSet [fg:symbols:vpn.filtersets:TunnelFilterSet] [fg:symbols:vpn.filtersets:L2VPNFilterSet] [fg:symbols:vpn.filtersets:TunnelGroupFilterSet].

**REST API**: `api/serializers.py` is a 3-line re-export shim over `api/serializers_/{crypto,tunnels,l2vpn}.py` [code:netbox/vpn/api/serializers.py:1-3]. `api/views.py` holds one NetBoxModelViewSet per model plus VPNRootView; `api/urls.py` registers ten routes on a NetBoxRouter [code:netbox/vpn/api/urls.py:4-15] [fg:entrypoints:vpn.api.views] [fg:entrypoints:vpn.api.urls].
