# ipam — subsystem map (NetBox @ ea4c205)

## What it is

The `ipam` Django app holds IP address space (RIR, Aggregate, Prefix, IPRange, IPAddress), routing context (VRF, RouteTarget), autonomous systems (ASNRange, ASN), layer-2 domains (VLANGroup, VLAN, VLANTranslationPolicy, VLANTranslationRule), first-hop redundancy (FHRPGroup, FHRPGroupAssignment) and layer-4 services (ServiceTemplate, Service). It is 69 modules and 18,159 lines of code with 7 test modules. [fg:subsystems:ipam] [code:netbox/ipam/models/__init__.py:1-7]

## Entry points

- Project URLs mount `ipam.urls` at `ipam/` and `ipam.api.urls` at `api/ipam/`. [code:netbox/netbox/urls.py:30] [code:netbox/netbox/urls.py:49]
- `ipam/urls.py` has exactly two `path()` lines per model (`detail=False` and `<int:pk>/`) using `get_model_urls`; the actual routes come from `@register_model_view` decorators in `views.py`, which is why `urls.py` imports `views` only for its side effect. [fg:entrypoints:ipam.urls] [code:netbox/ipam/urls.py:1-16]
- `api/urls.py` registers 18 viewsets on `NetBoxRouter` and adds five explicit paths for `available-asns`, `available-ips` (prefix and ip-range), `available-prefixes`, `available-vlans`. [fg:entrypoints:ipam.api.urls] [code:netbox/ipam/api/urls.py:7-59]
- `IPAMQuery` exposes singular/list fields for 18 types and is merged into the project schema. [code:netbox/ipam/graphql/schema.py:9-63] [code:netbox/netbox/graphql/schema.py:11]
- Signal receivers: Prefix `post_save`/`post_delete` maintain the hierarchy cache; IPAddress `pre_delete` clears primary/OOB IP on Device and VirtualMachine. [fg:entrypoints:ipam.signals] [code:netbox/ipam/signals.py:29-76]
- `rebuild_prefixes` management command resets `_depth`/`_children` and rebuilds per VRF. [fg:entrypoints:ipam.management.commands.rebuild_prefixes] [code:netbox/ipam/management/commands/rebuild_prefixes.py:10-27]
