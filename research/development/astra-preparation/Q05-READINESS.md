# First replacement family prepared

15 September 2026. Q05 is prepared and checked. It has not been sent to Astra or Fable.

This is material for testing the reviewers, not a guide produced by the interpretation layer. We prepared examples with justified answers so that a later model response can be checked against something more dependable than another model's opinion.

## What is ready

Q05 covers a different underlying decision from the families used during the repair. It contains six challenges for each of the three Phase 1 roles: the verifier, guidance assessor and assessor of verifier decisions. That is 18 distinct items. Each will eventually be attempted twice under the existing qualification design.

The examples include supported guidance, a valid alternative, an unsupported assertion, a missed exception, missing information and conflicting evidence. The guide omission is partial, so a reviewer must recognise the rules that remain correct while identifying the missing one. The revised bank still needs an empty guide elsewhere. A fictional deployment conflict is labelled as such; it is not presented as a historical owner decision.

The proposed role instructions were not changed while preparing this family. Expected answers, source review and serious error definitions remain separate from the permitted model inputs.

## Why we can check the answers

The case uses exact source revisions and documentation excerpts. The installed implementation matched the pinned implementation used for the behaviour checks.

Thirteen authored scenarios reproduced the expected behaviour. Four deliberate changes to that implementation produced wrong results that the checks detected. These are observations within one family, not seventeen independent cases. No upstream test suite was run.

The investigator reviewed the expected decisions against the source passages and observations, including scope, legitimate alternatives, omissions and unresolved authority. This supports the reference answers, but it is not independent human certification or proof that every possible reference error has been found.

## Preparation checks

All 18 items passed source identity, citation, input separation, candidate identity and output format checks. Authored example answers also passed the existing format validators; those are schema witnesses, not model responses.

The request builder rejected an altered instruction, an altered source and an injected answer key. These three checks establish those specific input controls. They do not establish the live provider's behaviour or the absence of prior model knowledge.

The first packet version exceeded the existing input allowance for six requests. It is preserved. A second version removes repeated metadata and presents the same observations more compactly. It retains the source evidence, expected verdicts and role instructions. All 18 revised requests fit the development bound. The largest request plus padding is 32,755 against an allowance of 32,768, using the offline configuration. Any later input change needs another size check. Actual provider token accounting remains unverified.
