## Reference review and reconciliation

The separate review supported D1, D3, D4 and D6, challenged the scope of D2, and supported D5 while questioning the documentation's example. Its initial answer is preserved. We ran [twelve focused local checks](fable-h06-check-results.json) using the pinned source to investigate the concrete objections. All twelve matched the expectations declared in [the check script](fable_h06_checks.py). These are checks of software behaviour, not twelve model tests.

| Fable observation | What the check established | Decision |
| --- | --- | --- |
| The request body flag loads the initial request, not every new request later created inside the flow. | In both modes, the initial body was available, but accessing a new unread request's content raised `RequestNotRead`. The reads occur before the adapter's loop at `_auth.py` 71 to 75 and 96 to 100. | Accept this scope clarification for D2. |
| The exception for an already loaded body should require a body known to be backed by `ByteStream`, or be removed. | A body originally supplied as a stream worked without the flag after an explicit read, in both modes. The unread control failed. `_models.py` 472 and 486 check for cached content. | Reject the proposed restriction. The existing exception requires content already to be loaded; Fable's counterexample instead leaves it unread. The reference does not authorise assuming that every incoming body is loaded. |
| The response body flag can buffer the final response even when the caller requests streaming. | Both client modes returned a consumed and closed response with the flag, and an unconsumed open response without it, using a mock transport. | Add this supported consequence beside D3. It is not a measured memory or performance result. |
| The documented async rejection example does not preserve the async generator contract. | Its method body raised `AttributeError` in client dispatch, with an unawaited coroutine warning. Preserving the generator contract raised the intended `RuntimeError`. The final error concerned `aclose`, with `__anext__` recorded as its preceding cause. | Accept the caveat for D5. The earlier local probe already included an unreachable `yield`; it did not test the documentation example verbatim. The valid option to refuse an unsupported mode is unchanged. |

The review also suggested documenting redirects, response history and cleanup. Those are adjacent behaviours, not demonstrated omissions from the six declared rules. We do not expand the Phase 1 reference or add tests for them in this step. The concurrency concern remains outside the evidence we have established.

### Reference revision for future use

This report is the H06 reference addendum dated 14 September. The original reference JSON, authored guide and historical run remain unchanged. Future H06 packets must include the precise evidence above and these qualifications:

* D2 concerns the initial request passed to the default adapter. A later request created inside the flow needs its own body preparation if the flow accesses that content. The exception for content already loaded remains valid.
* D3 concerns loading before the flow resumes. With the flag set, that includes the final response and can consume a response requested in streaming mode.
* D5 permits explicit rejection of an unsupported mode. An asynchronous override must preserve the interface the client consumes if it is to raise the intended exception. Do not copy the documentation example uncritically.

The first guidance review did not raise these qualifications. The second review had a different job and input, so this is not a controlled comparison of the two prompts. It demonstrates useful challenges and a mistaken objection in one public development case. It does not estimate assessor accuracy or show that Fable outperforms Astra. Astra has not supplied a separate blinded assessment of this guide; Codex's evidence reconciliation is investigator work.

To reproduce the local checks, use the existing Phase 1 Python environment and run `fable_h06_checks.py --source PATH_TO_PINNED_HTTPX --output NEW_OUTPUT_PATH`. The script verifies the full existing source manifest before import, records its own hash and dependency versions, uses local adapters and mock transport, and refuses to overwrite an existing result. It does not make network or model requests.
