# Review the evidence actually supplied to each role

16 September 2026. This is an investigator preparation procedure. It does not qualify a model or authorise a run.

## Required review record

For every distinct packet, bind the review to its exact bytes, role instruction, response schema and proposed scoring key. Review the final materialised packet, after source extraction and truncation. A review of the full upstream archive is insufficient. Keep this investigator record and scoring key outside the role's allowed inputs.

For every submitted claim and reference coverage unit, record:

1. Its exact text, scope and expected decision, including alternatives allowed by the key.
2. The permitted source file, hash and line span that establish or contradict the decision. Explain the inference in full. A valid citation or a matching hash alone does not establish support.
3. Every called dependency needed for that inference. Locate its supplied implementation or an applicable explicit documentation contract. If the necessary effect is missing, record the limit; do not infer it from a function name or investigator knowledge.
4. Each observation used, with the tested input, options, runtime and source revision, command or test body, actual outcome and exception handling. Name both expected and actual fields. An opaque observation ID and a result alone are insufficient. State whether the observation establishes an example or the entire claimed scope.
5. Any missing evidence, competing reading, unsupported reference assertion or incorrect key. Keep a deliberate missing-evidence test separate from a case that accidentally lacks evidence for its central requirement.
6. The reviewer's identity and limitations. A second pass by the same investigator is not independent human certification.

Check each role separately. An assessor may receive a reference that a verifier does not; a reference assertion cannot repair a missing source merely by repeating the desired answer. Check a correct alternative and a plausible wrong alternative under the same inputs and settings. Inspect every scope-limiting sentence at extraction boundaries.

## Acceptance before a new freeze

Every scored central requirement must have a defensible decision using only the final permitted packet. Resolve accidental ambiguity before freezing, or remove the affected item from the proposed scored bank under a documented design revision. Deliberate unresolved examples must have an explicitly justified unresolved key. Recheck all affected items and coverage units when a source changes, then repeat structural and size checks on the exact final packets.

During collection, preserve frozen inputs and keys. A discovered defect remains an unsuccessful original item with a separate diagnostic interpretation. Record all affected items, including unrun ones, without inventing responses or retroactively passing qualification. If model feedback informs repair, the exposed family is development material.
