# First fresh-task comparison: no observed correctness advantage

16 September 2026. One newly authored, bounded API change; one repository guide prepared without the request; two fresh coding attempts, with the guide supplied to one. The user approved exactly these three sessions. All completed once, and the allocation is closed.

| Common check | Ordinary coding | Coding with guide |
|---|---:|---:|
| Acceptance checks | 9/9 passed | 9/9 passed |
| Existing relevant regression cases | 104/104 passed | 104/104 passed |

Both attempts produced essentially the same core implementation. Existing implementation methods and test functions were preserved. The extra tests authored by each agent passed too; their different counts are not quality scores. No output was repaired after the common evaluation.

**Result:** this task shows no correctness advantage from supplying the guide. Preparation added effort. This is a retained null result on one small task, not proof of equivalence across tasks or evidence that guidance never helps. The explicit task requirements and limited complexity may leave little for a general repository guide to add.

## What was controlled, and what was not

The source archive was pinned and verified; all three initial source directories contained the same 125 files. Both coding conditions received identical task requirements and execution instructions, with only the saved guide added to one. The guide's content was frozen before coding; only source-link prefixes were normalized. Common evaluator tests were saved before outputs and checked unchanged afterward. All contexts used the same model and reasoning setting. Raw inputs, first outputs, code, tests and usage are retained privately.

Recorded tool calls showed no access to the other candidate, held-out evaluator or private study records. General parent-project instructions were nevertheless inherited, and tools were not confined by an operating-system read boundary. This is an exploratory comparison with observed input restrictions, not certified isolation or a qualified formal pilot. The guide had author citations, not independent assessor certification; no Fable assessment is claimed.

The focused regression command omitted global test fixtures and did not run the full upstream suite, coverage, linting or strict typing. Session timing included tool and approval delays, and preparation must be counted; the small difference between coding times is not evidence of a speedup. No economic benefit is established.

## Next step

Keep qualification paused and review whether a further task has a concrete reason for repository guidance to help. Retain this result. No new task, qualification cycle or model allocation starts automatically.
